# UX audit of the whole app — ranked, with fix stages

Audit date: 2026-10-18. Method: a heuristic review of the code (working tree), done by three read-only scouts plus
the main loop. The app was not run, so items marked *inferred* need a manual check. Paths are under
`src/main/java/dev/kamil/fabric/` unless they start with `src/`.

Rules used: Nielsen's 10 heuristics (H1–H10), Krug (Don't Make Me Think, Trunk Test), Fitts's law (target
spacing), WCAG 2.1 AA (contrast 4.5:1 for text, 3:1 for UI parts, visible focus), and readable line length.

**Score: 3 / 10.** 9 of the 10 quick-diagnostic checks fail in at least one window. No core task is fully blocked
(the keyboard paths work), so the score is not lower. Target after stages 1–5: 9 / 10.

> **Before any stage:** another session has uncommitted edits in many of these files (Tasks, Processes, Changes,
> Notes, Water, BodyDouble, FabricManagerApp, app.css, plus new E2E tests). Commit or finish that work first. If
> you don't, every stage below edits the same files at the same time.

### Later (severity 1–2, small or local)

- Enter in the project picker opens a new session even when a saved session is selected (`session/ProjectPicker.java:117`).
- In the branch popup, a single click only selects and nothing says "double-click" (`git/BranchPopup.java:231`).
- Ctrl+Shift+D is bound twice, as split and as duplicate (`terminal/TerminalTab.java:595`, `FabricManagerApp.java:332`).
- Toasts: the x is tiny, and evicting an old toast logs a water reminder as "missed" (`toast/Toasts.java:61,83`).
- Mixed names for the same thing:
  - "waiting for you" and "needs input" (`session/SessionSidebar.java:670`, `session/AgentsPanel.java:157`)
  - "Settings", "Claude settings" and "Claude config browser"
  - the ▤ icon for both Processes and Servers (`FabricManagerApp.java:298,319`)
- Tasks: there is no way to edit a task's text, and Done expands by mouse only (`tasks/TasksWindow.java:244`).
- The Claude settings "dirty" prompt has no Save option (`claude/ClaudeSettingsWindow.java:301`).
- Body double: after Enter in the URL field, Space, ← and → type into the field (*inferred*, `bodydouble/BodyDoubleWindow.java:165`).
- English: Remove has no inline Undo, and the reading column is 1400 px wide.

## Decisions

- **One rule per behaviour, app-wide:**
  - Esc closes or goes back.
  - Space or Enter does the highlighted primary action.
  - Delete always gets an undo bar, not a confirm.
  - Every window shows its keys in one footer hint line (the SnippetPicker pattern) or in the button label.
- **Undo beats confirm** (H3). The Notes undo bar becomes the shared component for deletes.
- **English Next (→)** always moves to the next card:
  - Review front: Next skips. The card keeps its progress and stays due.
  - Review back: Next = done (Good).
  - Learn: Next = today's Skip, and N still works.
  - Full detail: `~/.claude/plans/check-check-all-back-jolly-hopper.md`.

## Stages

1. **Stop silent data loss** — findings 1, 2, 3, 4, 9, 15. About 2 h. — done 2026-10-18
   Extract the Notes undo bar into a shared `UndoBar`, and use it in Tasks, Snippets and the Project picker. Shell
   tabs with live children ask before closing. Notes: Ctrl+Delete acts only when the list has focus; a failed save
   shows in red and asks on close. `Dialogs.confirm`: Cancel is the default. Clone: confirm a cancel while running.
   Done when: E2E tests show that Delete in Tasks, Snippets and the Project picker can be undone; Ctrl+Delete in
   the Notes body keeps the note; Enter in a confirm dialog cancels; `./gradlew test` is green.
2. **English flow** — findings 5, 17, plus the Home key line. About 1.5 h. — done 2026-10-18
   Add the `CardFrame` (header with Home and mode, fixed Back/Next/Remove bar) and "Show answer" on the Review
   front. Add `Deck.skip()` and `Deck.position()`, the → key, Enter = Space, and Home in Sentences.
   Done when: the E2E tests in `src/test/java/dev/kamil/fabric/english/` cover Show answer, Next skips without
   writing, Back after a skip, → in Learn and Review, and Sentences Home; `./gradlew test` is green.
3. **One close and back rule** — findings 6, 8, 16. About 45 min. — done 2026-10-18
   Add `Dialogs.closeOnEscape` to 7 windows. The Overview closes on a sidebar click. Changes reuses its window.
   Done when: one parameterised E2E test opens each of the 7 windows and Esc closes it; `./gradlew test` is green.
4. **Visible primary action and keys** — findings 10, 11. About 1.5 h. — done 2026-10-18
   Add `.button.primary`. In Changes, Enter commits and Commit is disabled while the message is blank. Add a footer
   hint line in Notes, Tasks, Changes, Processes and Body double. Add Overview numbers and a header. Add a key
   cheat sheet (F1). Update README.
   Done when: every window in the inventory has either a primary-styled button or a hint line; README lists every
   accelerator in `FabricManagerApp`; `./gradlew test` is green.
5. **Honest status** — findings 7, 12, 13, 14. About 1.5 h. — done 2026-10-18
   - Disable selection-dependent buttons. Add inline errors.
   - Show "No results", "Unreachable: …", "Saved" and "N hidden".
   - Set the muted colour to `#9a9390`, make `.history-meta` global, and add selected/focused cell rules.
   Done when: `SelectionContrastE2ETest` and the new tests are green; `./gradlew build` is green.
