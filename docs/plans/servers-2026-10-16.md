# Servers window

Show every fleet server, which apps run on each one, and each app's status
(up/down, version, uptime). Agentless: one system `ssh` call per server per poll.

## Decisions

- **No agent, no new library.** Run the system `ssh` binary with `ProcessBuilder`, as
  `Tool.ssh` already does. It already reads `~/.ssh/config`, the keys, the agent and
  known_hosts. Options: `-o BatchMode=yes -o ConnectTimeout=5 -o ControlMaster=auto
  -o ControlPath=~/.cache/fabric-manager/ssh-%C -o ControlPersist=60`.
  Rejected: Portainer, Komodo, Beszel and Dozzle (they need an agent on each server);
  Coolify (it is a PaaS and wants to own the server); Apache MINA SSHD (it would
  repeat what `ssh` already does).
- **Inventory comes from deployment-center, not a copy.** Read
  `<deployment-center>/projects/*/fleet.env` (`SSH_HOST`, `REMOTE_DIR`, `REMOTE_DIR_TEST`).
  The distinct `SSH_HOST` values are the servers. Compose projects found on a server
  but not in any fleet.env show as "unmanaged". The deployment-center path is a
  setting, with default `~/Documents/Projects/deployment/deployment-center`.
- **Version = the git SHA from `~/.fleet-state/<REMOTE_DIR>/current`** (short form),
  falling back to the image tag `backend-<sha>`.
- **Uptime = `State.StartedAt`** from `docker inspect`. Health = `State.Health.Status`.
  App status: **up** = all containers running and none unhealthy; **degraded** = some
  are; **down** = none running, or the stack is missing; **unknown** = the server is
  unreachable.

Verified on `hetzner` on 2026-10-16:
- `docker compose ls --format json` returns a JSON array (`Name`, `Status`, `ConfigFiles`).
- `docker inspect` returns `.State.Status`, `.State.StartedAt`, `.State.Health.Status`
  and `.Config.Image`.
- `~/.fleet-state/<dir>/current` holds a full SHA.

## Probe (one ssh call)

```sh
docker compose ls --all --format json
echo '---'
docker ps -aq | xargs -r docker inspect --format '{{json .Name}} {{json .State.Status}} {{json .State.StartedAt}} {{if .State.Health}}{{json .State.Health.Status}}{{else}}null{{end}} {{json .Config.Image}} {{json (index .Config.Labels "com.docker.compose.project")}}'
echo '---'
for f in ~/.fleet-state/*/current; do echo "$(basename "$(dirname "$f")") $(cat "$f")"; done
```

## Stages

1. **[done 2026-10-16] Probe and parser.** `servers/ServerProbe` builds the ssh command; `servers/ProbeParser`
   turns its output into `ServerStatus`/`AppStatus` records. Unit tests use captured
   output, including an unreachable server and a stopped stack.
   Done when: `./gradlew test` is green.
2. **[done 2026-10-16] Inventory.** `servers/FleetInventory` reads `fleet.env` files into `Server` →
   expected apps (project, env, remote dir), and merges the probe result with it.
   Done when: tests are green, and on the real deployment-center it lists `hetzner`
   (perkbill prod and test) and `nlp` (nlp prod and test; the alias was renamed from `next-crew` on 2026-10-16 and shows as unreachable until `~/.ssh/config` has `Host nlp`).
3. **[built 2026-10-16, Ctrl+Shift+M; awaiting hand test] Window.** `servers/ServersWindow` (copy of the `WaterWindow` shape): a server list
   with a status dot on the left, an app table on the right (App, Env, Status, Version,
   Uptime, Health) and a Refresh button. It polls every 30 s while open, on a daemon
   executor, and updates the UI through `Platform.runLater`. The Servers sidebar Action
   sits next to SSH in `FabricManagerApp`.
   Done when: `./gradlew run` shows live perkbill status from `hetzner`.
4. **Alert (optional).** A toast when an app goes from up to down, or a server becomes
   unreachable.
   Done when: stopping a test container shows a toast within one poll.

Later: an HTTP `/api/actuator/health` check, a "Logs" button (opens an SSH tab with
`docker compose logs -f`), and `bin/fleet` Actions per app.
